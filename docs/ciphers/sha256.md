# SHA-256 (Secure Hash Algorithm 256-bit)

## 1. Overview

**SHA-256** is a cryptographic hash function that produces a 256-bit (32-byte) hash value. Part of the SHA-2 family designed by the NSA and published by NIST in 2001, it remains one of the most widely used hash functions in security applications.

### Historical Context
- **1993**: SHA-0 published (withdrawn)
- **1995**: SHA-1 released (now deprecated)
- **2001**: SHA-2 family (including SHA-256) standardized
- **2017**: SHA-1 collision demonstrated
- **Present**: SHA-256 widely deployed, used in Bitcoin

## 2. Mathematical Foundation

### 2.1 Problem Definition

**Input**: Message $M$ of arbitrary length
**Output**: 256-bit hash $H$ (64 hex characters)

**Properties**:
1. **Deterministic**: Same input always produces same output
2. **Efficient**: Fast to compute
3. **Pre-image resistant**: Given $H$, infeasible to find $M$
4. **Second pre-image resistant**: Given $M_1$, infeasible to find $M_2$ where $H(M_1) = H(M_2)$
5. **Collision resistant**: Infeasible to find any $M_1, M_2$ where $H(M_1) = H(M_2)$

### 2.2 Mathematical Primitives

#### Bitwise Operations
- **AND**: $x \land y$
- **XOR**: $x \oplus y$
- **NOT**: $\lnot x$
- **Right Rotate**: $ROTR^n(x) = (x \gg n) \lor (x \ll (32-n))$
- **Right Shift**: $SHR^n(x) = x \gg n$

#### Logical Functions
$$Ch(x,y,z) = (x \land y) \oplus (\lnot x \land z)$$
$$Maj(x,y,z) = (x \land y) \oplus (x \land z) \oplus (y \land z)$$
$$\Sigma_0(x) = ROTR^2(x) \oplus ROTR^{13}(x) \oplus ROTR^{22}(x)$$
$$\Sigma_1(x) = ROTR^6(x) \oplus ROTR^{11}(x) \oplus ROTR^{25}(x)$$
$$\sigma_0(x) = ROTR^7(x) \oplus ROTR^{18}(x) \oplus SHR^3(x)$$
$$\sigma_1(x) = ROTR^{17}(x) \oplus ROTR^{19}(x) \oplus SHR^{10}(x)$$

### 2.3 Constants

#### Initial Hash Values (H0)
First 32 bits of fractional parts of square roots of first 8 primes:
```
H0 = 0x6a09e667  (√2)
H1 = 0xbb67ae85  (√3)
H2 = 0x3c6ef372  (√5)
H3 = 0xa54ff53a  (√7)
H4 = 0x510e527f  (√11)
H5 = 0x9b05688c  (√13)
H6 = 0x1f83d9ab  (√17)
H7 = 0x5be0cd19  (√19)
```

#### Round Constants (K)
First 32 bits of fractional parts of cube roots of first 64 primes.

## 3. Algorithm Description

### 3.1 Intuition

SHA-256 works like a complex blender:
1. **Pad** the message to a multiple of 512 bits
2. **Divide** into 512-bit blocks
3. For each block, **mix** extensively using logical operations
4. **Combine** with running hash state
5. Output final state as hash

The mixing ensures any change to input causes dramatic, unpredictable changes to output (avalanche effect).

### 3.2 Pseudocode

```
FUNCTION SHA256(message):
    // Preprocessing
    padded ← Pad(message)                    // Pad to 512-bit multiple
    blocks ← Split(padded, 512)              // Split into 512-bit blocks
    
    // Initialize hash values
    H[0..7] ← H0_CONSTANTS
    
    // Process each block
    FOR each block in blocks:
        // Prepare message schedule (64 words)
        W[0..15] ← block split into 16 32-bit words
        FOR t FROM 16 TO 63:
            W[t] ← σ₁(W[t-2]) + W[t-7] + σ₀(W[t-15]) + W[t-16]
        
        // Initialize working variables
        a, b, c, d, e, f, g, h ← H[0..7]
        
        // 64 rounds of compression
        FOR t FROM 0 TO 63:
            T₁ ← h + Σ₁(e) + Ch(e,f,g) + K[t] + W[t]
            T₂ ← Σ₀(a) + Maj(a,b,c)
            h ← g
            g ← f
            f ← e
            e ← d + T₁
            d ← c
            c ← b
            b ← a
            a ← T₁ + T₂
        
        // Add to hash state
        H[0..7] ← H[0..7] + [a,b,c,d,e,f,g,h]
    
    RETURN Concatenate(H[0..7])
```

### 3.3 Padding Scheme

```
Message: M
Length: L bits

Padded message:
[M][1][000...0][L as 64-bit big-endian]
       ↑
       k zeros where (L + 1 + k) ≡ 448 (mod 512)
```

**Example**: "abc" (24 bits)
```
01100001 01100010 01100011 1 [423 zeros] [0...011000]
    a        b        c    ^              24 in 64 bits
                          padding bit
```

### 3.4 Step-by-Step Example

**Input**: "abc"

1. **Padding**: "abc" + padding bit + zeros + length = 512 bits
2. **Initial state**: H[0..7] = H0 constants
3. **Message schedule**: Expand 16 words → 64 words
4. **64 rounds**: Mix with constants and schedule
5. **Final hash**: 
   ```
   ba7816bf 8f01cfea 414140de 5dae2223 
   b00361a3 96177a9c b410ff61 f20015ad
   ```

## 4. Complexity Analysis

### 4.1 Time Complexity

| Operation | Complexity | Notes |
|-----------|------------|-------|
| Preprocessing | O(n) | Padding |
| Per block processing | O(1) | 64 rounds, fixed operations |
| Total | **O(n)** | n = message length in bits |

**Detailed breakdown**:
- Message schedule expansion: 64 iterations
- Compression: 64 rounds
- Each round: ~10 operations
- Total per 512-bit block: ~700 operations

### 4.2 Space Complexity

| Component | Space |
|-----------|-------|
| Hash state | 256 bits (8 × 32-bit words) |
| Working variables | 256 bits |
| Message schedule | 2048 bits (64 × 32-bit words) |
| Total | **O(1)** constant |

Streaming mode possible: O(1) space regardless of message size.

## 5. Implementation Notes

### 5.1 Rust-Specific Considerations

```rust
/// Process a single 512-bit block
fn process_block(state: &mut [u32; 8], block: &[u8; 64]) {
    // Message schedule
    let mut w = [0u32; 64];
    for (i, chunk) in block.chunks_exact(4).enumerate() {
        w[i] = u32::from_be_bytes(chunk.try_into().unwrap());
    }
    
    // Expand
    for i in 16..64 {
        w[i] = sigma1(w[i-2])
            .wrapping_add(w[i-7])
            .wrapping_add(sigma0(w[i-15]))
            .wrapping_add(w[i-16]);
    }
    
    // 64 compression rounds...
}
```

**Key implementation details**:
- Uses `wrapping_add` for modular arithmetic
- Big-endian byte order
- Const arrays for K and H0 values
- All operations on 32-bit words

### 5.2 Edge Cases

| Case | Handling |
|------|----------|
| Empty message | Valid: produces known hash |
| Exact 512-bit message | Still needs padding block |
| Very long messages | Length stored as 64-bit (max 2^64 - 1 bits) |
| Binary data | Works on bytes, not just text |

### 5.3 Avalanche Effect Demonstration

```
SHA256("abc") = ba7816bf8f01cfea...
SHA256("abd") = a52d159f262b2d4e...  ← 1-bit change, completely different hash
SHA256("ABC") = b5d4045c3f466fa9...  ← Case change, completely different hash
```

## 6. Security Analysis

### 6.1 Security Level

| Attack | Complexity | Notes |
|--------|------------|-------|
| Pre-image | 2^256 | Finding m given H(m) |
| Second pre-image | 2^256 | Finding m2 given m1 |
| Collision | 2^128 | Birthday paradox |
| Length extension | Possible | Use HMAC for keyed hashing |

### 6.2 Known Weaknesses

| Issue | Severity | Mitigation |
|-------|----------|------------|
| Length extension | Medium | Use HMAC-SHA256 |
| Side-channel | Implementation-dependent | Constant-time code |
| None cryptographic | N/A | SHA-256 remains secure |

### 6.3 Comparison with Other Hash Functions

| Function | Output | Security | Speed |
|----------|--------|----------|-------|
| MD5 | 128 bits | Broken | Fast |
| SHA-1 | 160 bits | Broken | Medium |
| **SHA-256** | 256 bits | Secure | Medium |
| SHA-512 | 512 bits | Secure | Faster on 64-bit |
| SHA-3-256 | 256 bits | Secure | Varies |

## 7. Real-World Applications

### 7.1 Common Use Cases

| Domain | Application |
|--------|-------------|
| Cryptocurrency | Bitcoin mining, block hashing |
| TLS/SSL | Certificate fingerprints |
| Digital Signatures | Message digests for RSA/ECDSA |
| Password Storage | With proper salting (prefer Argon2) |
| File Integrity | Checksums, deduplication |
| Git | Commit object hashing |

### 7.2 Not Recommended For

| Use Case | Better Alternative |
|----------|-------------------|
| Password hashing | Argon2, bcrypt, scrypt |
| Key derivation | HKDF, PBKDF2 |
| Message authentication | HMAC-SHA256 |
| Short hash needs | BLAKE3 |
